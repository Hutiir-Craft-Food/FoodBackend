# Загальна архітектура

## Модуль забезпечує:
- Завантаження декількох зображень `(<=5)` для продукту
- Обробку (rotation, crop, resize)-  
- Нормалізацію розміру
- Видалення альфа-каналу
- Конвертацію в JPEG
- Збереження декількох варіантів розмірів
- Гарантію унікальності позицій та розмірів

## Пайплайн обробки зображення
### Послідовність обробки
1. Зчитування байтів з MultipartFile
2. Читання EXIF-метаданих
3. Автоматичний поворот (rotation) відповідно до EXIF
4. Нормалізація розміру (максимальний розмір ORIGIN)
5. Обрізання під різні співвідношення сторін
6. Resize до необхідних розмірів
7. Видалення альфа-каналу (якщо присутній)
8. Конвертація в JPEG
9. Збереження у storage

## Розміри зображень (Image Variants)

| Size       | Призначення         | Розміри                          |
|------------|---------------------|-----------------------------------|
| LARGE      | Нормалізований origin | 1080×1920 або 1920×1080          |
| MEDIUM     | Квадратний preview  | 438×438                           |
| SMALL      | Card preview        | 324×257 або 257×324               |
| THUMBNAIL  | Мініатюра           | 64×64                             |

* SMALL формується шляхом центрованого crop під співвідношення 324:257,
тому можливе вертикальне або горизонтальне представлення залежно від орієнтації.

## Нормалізація ORIGIN

``ORIGIN_W = 1080``

``ORIGIN_H = 1920``

- Якщо зображення вертикальне — 1080×1920
- Якщо горизонтальне — 1920×1080
- Зберігається пропорція сторін
- Масштабування без спотворення

## Підтримка EXIF Rotation
### Підтримуються значення:

| EXIF Orientation | Поворот |
|------------------|----------|
| 3                | 180°     |
| 6                | 90°      |
| 8                | 270°     |

- Якщо EXIF відсутній — зображення не обертається
- Метадані не зберігаються після обробки

## Альфа-канал
Усі зображення зберігаються у форматі JPEG.

Якщо зображення містить альфа-канал (PNG, WebP тощо):

- Альфа видаляється
- Фон заповнюється білим кольором
- Конвертація відбувається до BufferedImage.TYPE_INT_RGB

## Збереження у Storage
### Генерація імені файлу

```{size}_{UUID}.jpg```
- Використовується UUID
- Імовірність колізії практично відсутня
- Усі файли зберігаються у форматі .jpg

## Обмеження:
### Максимальна кількість зображень
- Максимум 5 зображень на продукт

### Унікальність позиції
#### Для одного продукту:
``UNIQUE(product_id, position)``

### Унікальність варіанта розміру
#### Для одного image:
``UNIQUE(image_id, size)``
- Один розмір одного типу може існувати лише один раз

### MIME валідація
#### Підтримуються лише MIME-типи, зазначені в конфігурації:
``allowed.mime.types=image/jpeg,image/png,image/webp``
- Валідація відбувається через Apache Tika
- Перевіряється фактичний MIME, а не розширення файлу

### Операції API
#### Завантаження зображень
``POST /v1/products/{productId}/images``
##### Body (meta):
```
{
  "images": [
    { "position": 1 },
    { "position": 2 }
  ]
}
```

##### Files (multipart):
```files: image1.jpg, image2.png```

- Порядок файлів відповідає порядку meta.images
- Позиція визначається явно

#### Отримання зображень
``GET /v1/products/{productId}/images``

#### Зміна порядку (reorder)
``PUT /v1/products/{productId}/images``

#### Видалення зображення
``DELETE /v1/products/{productId}/images``

#### Видалення зі Storage
##### При видаленні з БД:
- Викликається storageService.deleteByUrl()
- Видаляються всі варіанти розмірів
- Забезпечується консистентність
- 
#### Транзакційність
- Завантаження зображень відбувається у межах @Transactional
- Порушення UNIQUE-constraint перехоплюється
- Позиції гарантують консистентність

#### Внутрішні гарантії модуля
- Завжди зберігається 4 варіанти зображення
- Всі зображення зберігаються у JPEG
- EXIF rotation підтримується
- Альфа-канал видаляється
- Позиції строго унікальні
- Розміри строго унікальні
